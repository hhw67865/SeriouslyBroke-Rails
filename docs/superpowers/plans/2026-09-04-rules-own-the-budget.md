# Rules Own the Budget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every budget figure lives on a rule — a target moves off categories, a per-period rule can build up (capped or not), every rule carries a type that orders the give-way walk, and the rules form writes every shape by hand.

**Architecture:** Three columns on `budgets` (`carries_over`, `target_amount`, `rule_type`) and one migration moving `categories.target_amount` across; `ClaimCalculator#shape` grows a `:building` arm and a `capped?` predicate (no formula change); one form object (`RuleForm`) maps the user's words (how often / unspent money / target / type) onto the columns; the Budget page gains a type overview and the shortfall walk sorts by type before priority. Physical ledger untouched.

**Tech Stack:** Rails 8.1, RSpec/Capybara, `ClaimCalculator`/`ClaimLedger`, `Budget` validations, `User#period_boundaries`.

**Spec:** `docs/superpowers/specs/2026-09-04-rules-own-the-budget-design.md` — §2.1's table is the acceptance test for shapes; §3 for the type; §4 for the form.

## Global Constraints

- **No formula changes** (spec §2.1): a building rule is the existing §3.2 walk with the cap read off the rule (`capped?`); an uncapped rule has no `min(…, target)`. Every §2.1 row is pinned through `ClaimCalculator` with planted literals both directions.
- **One spelling**: shape from `ClaimCalculator#shape` (via `Budget#claim_shape`) only; the give-way order from ONE method (`HomePresenter#give_way_order`) sorting `[type rank, category priority, category name, rule order]`; the how-often/columns mapping in `RuleForm` only.
- **Physical invariant untouched**: the migration writes no `account_movements`/`pools`/`entries`; raw-SQL pin before/after. Every category's claim identical before and after the target move (recomputed on planted fixtures).
- **Ledger-per-render** discipline kept: no screen builds a second `ClaimLedger`; strict-equality cost pins stay `eq`.
- Words: **bill / usage / choice**; **builds up / resets**; **target**; Home's words unchanged; "goal" leaves code and copy (a goal is a building rule with a target).
- `today` is `User#today`; `Date.current` never lazily inside `travel_to`; period arithmetic only via `User#period_boundaries`/`period_containing`.
- Session disciplines: single-line commits, explicit paths, **never push**; spec files one at a time with `ps -eo pid,command | grep "[r]spec" | grep -v "zsh -c"` empty first; `seeds_spec` ALONE; `rubocop -A` + re-run; dev DB is real data — `mingguan0809@gmail.com` only, throwaway signups for browser work; the four `claims-*.png` at repo root are never staged; Tailwind rebuild for new classes; true-375 via the CDP idiom.
