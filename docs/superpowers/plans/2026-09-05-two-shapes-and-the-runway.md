# Two Shapes and the Runway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Free is checking minus claimed; a rule is either every-period or by-a-date; Home is the runway with category blocks, Budget is the list of every category, and a new rule is its own page — all per the approved mocks.

**Architecture:** One migration converts building rules to dated one-offs and drops `carries_over`/`target_amount`; `ClaimCalculator` shrinks to two shapes and `ClaimLedger#free` to a subtraction; the screens are rebuilt on the same readers (`ClaimLedger`, `ClaimCalculator`, `HomePresenter#give_way_order`, `SuggestionEngine`) with three new presentation seams — a runway (`HomePresenter#runway`), category blocks (`HomePresenter#category_blocks`), and suggestions grouped by category (`SuggestionEngine#by_category`); the form's preview is rendered by the server over an unsaved rule.

**Tech Stack:** Rails 8.1, Turbo Frames + Stimulus, RSpec/Capybara, `User#period_boundaries`/`#period_containing`, existing design tokens (`custom.css`, `application.css`).

**Spec:** `docs/superpowers/specs/2026-09-05-two-shapes-and-the-runway-design.md` — §2 (model), §3 (Home), §4 (Budget), §5 (form), §6 (migration) are the acceptance criteria; the mocks at `claude.ai/code/artifact/a75c3e69-8da5-4ff8-83ad-2d6c46b49108` (tabs Home / Budget / New rule form) are the visual reference.

## Global Constraints

- **Free is `pot − total_claims`** (spec §2); nothing reads `unclaimed` or the cap after Task 1.
- **Two shapes**: `ClaimCalculator#shape ∈ {:rate, :dated}`; `:building`/`capped?`/`carries_over`/`target_amount` exist nowhere after Task 1; every rule's `amount > 0`.
- **One spelling**: give-way order only from `HomePresenter#give_way_order`; suggestions grouped only by `SuggestionEngine#by_category`; the form's preview per-period figure only from `ClaimCalculator#standing_ask`/`#planned_this_period` on the unsaved rule; period arithmetic only via `User#period_boundaries`/`#period_containing`; `today` is `User#today`.
- **Ledger-per-render**: Home, Budget, the form page each build ONE `ClaimLedger` (or one calculator on the form); strict-equality cost pins (`eq`), 1-vs-N.
- **Words**: in checking · free to spend · claimed · every period · by a date · bill / usage / choice · ready / short / overdue. Never: available, distribute, allocation, goal, fund, builds up, set aside on Home.
- **Physical invariant untouched** by the migration (raw-SQL pin); every category's claim identical before/after on planted fixtures.
- Session disciplines: single-line commits, explicit paths, **never push**; spec files one at a time with `ps -eo pid,command | grep "[r]spec" | grep -v "zsh -c"` empty first; `seeds_spec` ALONE; `rubocop -A` + re-run; dev DB is real data — `mingguan0809@gmail.com` only, throwaway signups for browser work; the four `claims-*.png` at repo root are never staged; Tailwind rebuild for new classes; true-375 via the CDP idiom; design tokens + `rounded`; `Date.current` never lazily inside `travel_to`.
